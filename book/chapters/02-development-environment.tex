\section{The Development Environment Used in This Book}
\label{sec:development-environment}

Image processing combines programming, numerical computation,
visualisation and experimentation. A development environment for this
kind of work therefore needs to support more than simply executing
Python programs.

Throughout this book the primary development environment consists of:

\begin{itemize}
    \item \textbf{Anaconda Distribution} for Python and the conda
    package-management system;
    \item \textbf{Python 3.14} as the target Python release series;
    \item \textbf{conda environments} for isolating the software
    dependencies used by the project;
    \item \textbf{Visual Studio Code} as the principal editor and
    development environment;
    \item the \textbf{Python extension for Visual Studio Code} for
    interpreter selection, editing, running and debugging Python code;
    \item the \textbf{Jupyter extension for Visual Studio Code} for
    executing the companion notebooks;
    \item \textbf{NumPy} for numerical arrays;
    \item \textbf{Matplotlib} for visualisation;
    \item \textbf{Pillow} for working with conventional image files;
    \item \textbf{pytest} for automated testing; and
    \item the \textbf{\pyimage{} package} developed progressively
    throughout the book.
\end{itemize}

Anaconda Distribution combines Python, conda, Jupyter and a broad
scientific-computing ecosystem within a single distribution
\cite{anaconda_distribution}. Conda environments allow different
projects to maintain separate Python versions and dependency sets
\cite{conda_environments}.

Visual Studio Code provides the common workspace in which the book,
Jupyter notebooks, Python package, tests and supporting project files
can all be edited.

\section{Why Python 3.14?}
\label{sec:python-314}

The project deliberately targets the Python 3.14 release series.

The environment definition therefore specifies:

\begin{minted}{yaml}
- python=3.14
\end{minted}

rather than leaving the Python version unconstrained.

This has two advantages. First, the examples, notebooks and tests can
be developed against a known language version. Second, a reader who
recreates the environment later will not silently receive a different
major or minor Python release.

The environment is not pinned to a specific patch release such as
\texttt{3.14.x}. Conda may therefore install the most appropriate
available Python 3.14 patch release for the platform.

\begin{implementationnote}
The project targets Python 3.14 throughout. If conda reports a
dependency-resolution problem on a particular platform, check whether
compatible builds of the requested packages are available for Python
3.14 before changing the project definition.
\end{implementationnote}

\section{Why Use an Isolated Environment?}
\label{sec:why-conda-environment}

It is possible to install packages directly into Anaconda's
\texttt{base} environment. For a substantial project, however, this
quickly becomes undesirable.

Different projects may require different versions of Python or of
individual libraries. Installing everything into one environment can
therefore result in dependency conflicts and makes it difficult to
determine exactly which packages a project requires.

A dedicated environment isolates those dependencies.

For this book the environment is called:

\begin{minted}{text}
image-processing-python
\end{minted}

and uses Python 3.14.

\section{Installing Anaconda Distribution}
\label{sec:install-anaconda}

Anaconda Distribution is available for Windows, macOS and Linux.
Installation procedures change over time, so this book deliberately
does not reproduce version-specific installer filenames.

The current installer and platform-specific instructions should be
obtained from the official Anaconda documentation
\cite{anaconda_install}.

After installation, verify conda from a terminal:

\begin{minted}{bash}
conda --version
\end{minted}

A second useful check is:

\begin{minted}{bash}
conda info
\end{minted}

The available environments can be displayed with:

\begin{minted}{bash}
conda info --envs
\end{minted}

\section{Creating the Book Environment}
\label{sec:create-conda-environment}

A conda environment can be created directly from the command line.

Open a terminal and enter:

\begin{minted}{bash}
conda create --name image-processing-python python=3.14
\end{minted}

Once creation has completed, activate the environment:

\begin{minted}{bash}
conda activate image-processing-python
\end{minted}

The terminal prompt will normally change to show the active
environment:

\begin{minted}{text}
(image-processing-python)
\end{minted}

Verify the selected Python release:

\begin{minted}{bash}
python --version
\end{minted}

The result should begin with:

\begin{minted}{text}
Python 3.14
\end{minted}

The interpreter location can also be inspected:

\begin{minted}{bash}
python -c "import sys; print(sys.executable)"
\end{minted}

\label{sec:install-packages}

Activate the project environment before installing packages:

\end{minted}

\begin{minted}{bash}

introduced when they are required. The intention is to implement and
understand the algorithms before relying upon higher-level
image-processing functions.

\section{Creating a Reproducible Environment File}
\label{sec:environment-yml}

At the root of the repository create:

\begin{minted}{text}
environment.yml
\end{minted}

with the following contents:

\begin{listing}[htbp]
    \caption{Initial conda environment definition targeting Python 3.14.}
    \label{lst:environment-yml}

\begin{minted}{yaml}
name: image-processing-python

channels:
  - defaults

dependencies:
  - python=3.14
  - numpy
  - matplotlib
  - pillow
  - jupyterlab
  - ipykernel
  - pytest
  - pip
\end{minted}

\end{listing}

The environment can then be created with:

\begin{minted}{bash}
conda env create --file environment.yml
\end{minted}

and activated with:

\begin{minted}{bash}
conda activate image-processing-python
\end{minted}

If the definition is subsequently changed, update the existing
environment with:

\begin{minted}{bash}
conda env update --file environment.yml --prune
\end{minted}

The \texttt{--prune} option removes dependencies that are no longer
present in the environment definition.

\section{The Python Interpreter and the Jupyter Kernel}
\label{sec:interpreter-kernel}

A Python interpreter and a Jupyter kernel are closely related but are
not exactly the same thing.

The interpreter executes Python programs. A Jupyter kernel is a
long-running computational process used to execute notebook cells.
Selecting the correct interpreter for source files therefore does not
guarantee that an already-open notebook is using the same
environment.

Open the notebook kernel selector and choose the environment
corresponding to:

\begin{minted}{text}
image-processing-python
\end{minted}

The Visual Studio Code Jupyter documentation describes notebook
execution using a selected Python environment and Jupyter kernel
\cite{vscode_jupyter}.

\section{Verifying Python 3.14 in a Notebook}
\label{sec:verify-python-version}

The companion notebook checks both the executable path and the Python
version.

A minimal check is:

\begin{listing}[htbp]
    \caption{Checking the Python release used by a notebook.}
    \label{lst:check-python-version}

\begin{minted}{python}
import sys

print(sys.executable)
print(sys.version)

if sys.version_info[:2] == (3, 14):
    print("PASS: Python 3.14")
else:
    print("FAIL: this project expects Python 3.14")
\end{minted}

\end{listing}

The notebook deliberately reports a failure rather than terminating.
This makes it useful for diagnosing an incorrectly selected kernel.

\section{Notebook Execution Discipline}
\label{sec:notebook-discipline}

Before considering a chapter notebook complete:

\begin{enumerate}
    \item save the notebook;
    \item restart the Jupyter kernel;
    \item run every cell from the beginning;
    \item confirm that no cell raises an unexpected error; and
    \item confirm that all figures and numerical results are
    regenerated correctly.
\end{enumerate}

\section{Troubleshooting}
\label{sec:ch02-troubleshooting}

\subsection{The Notebook Is Not Running Python 3.14}

Run:

\begin{minted}{python}
import sys
print(sys.version)
print(sys.executable)
\end{minted}

If the version does not begin with \texttt{3.14}, select the
\texttt{image-processing-python} kernel again.

\subsection{The Environment Does Not Appear in Visual Studio Code}

Confirm that conda can see it:

\begin{minted}{bash}
conda info --envs
\end{minted}

Then reopen the interpreter selector in Visual Studio Code
\cite{vscode_python_environments}.

\subsection{A Package Imports in the Terminal but Not in the Notebook}

Compare:

\begin{minted}{bash}
python -c "import sys; print(sys.executable)"
\end{minted}

with:

\begin{minted}{python}
import sys
print(sys.executable)
\end{minted}

Both should refer to the same Python 3.14 conda environment.

\section{Chapter Summary}
\label{sec:ch02-summary}

This chapter established the development environment used throughout
the remainder of the book.

Anaconda Distribution provides Python and conda, while a dedicated
conda environment isolates the project from the base installation and
from unrelated projects. The project explicitly targets the Python
3.14 release series through the \texttt{environment.yml} definition.

Visual Studio Code acts as the common development workspace. Its
Python support uses the selected conda interpreter for Python source
files, while its Jupyter support allows chapter notebooks to execute
using a kernel associated with the same environment.

The next chapter introduces the Python language features that are
particularly important when implementing image-processing algorithms.
